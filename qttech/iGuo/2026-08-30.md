# 2026-08-30 iGuo 自学日志：组织经验转结构的完整实践

> 主题：把今天的组织档案建设实践本身作为学习现场。参与者：iGuo（学习者）。按学习主题整理。

## 学习背景

今天全天的实际工作：重构 quanttide-org 的组织档案体系、搭建 qtorg 展示站、建立 learning-management 的日志与档案。这些工作同时是学习现场——下面提炼的是过程中实际学到的东西，不是工作汇报。

## 学习主题（今日证据）

今日学习横跨四个管理领域：组织管理（主题一）、资产管理（主题二）、机密管理（主题三）、学习管理（主题四）。

### 主题一：组织管理——形态判断与治理语言

**形态判断：复用 vs 新设的分辨**

实训基地形态经历四轮收敛：复用现有部门 / 单设预备部门 → 必须编进部门 → 简化版 → 内包子公司 → 职能部门编组（技术/产品/市场/综合）。

- 每一轮都在否决 AI 给的方案：预备部门违反"训练现场即真实组织"；纯复用丢失训练意图；最终形态用内包表达父子关系、用传统职能部门承载编组
- 学到：**形态判断的尺子是"训练现场即真实组织"，不是方案合理性**；AI 的方案要用自己的尺子砍

**治理的标准语言：民主与法治**

"内核不够透彻"的追问逼出组织模式的本质（把依赖"在场"的价值固化为记录与结构），随后自行补上定名："民主"和"法治"。

- 确认否决权不是反民主设计，而是"在场残余、熔断位"——受程序约束的兜底
- 学到：**给十年治理直觉配上理论词汇**——概念名正了，档案体系才能自洽表述

### 主题二：资产管理——档案结构即组织结构

orgs/people 分组、四件套（index/structure/institution/culture）、人物一等实体、站点与档案解耦、数据与展示分离。

- 每一次结构调整都是对"组织是什么"的回答：档案分组 = 组织分类；人物跨组织 = 人物一等实体
- 学到：**结构决策就是组织认知的显影**——"怎么分目录"和"组织是什么"是同一个问题

### 主题三：机密管理——脱敏是档案设计原则

Jerry 日志脱敏三连：代号化（鲍宇航→Jerry、张果→导师）→ 删来源（渠道、时间）→ git-filter-repo 全历史重写。两轮 filter-repo 实操。

- 学到：**隐私不是一次操作，是档案设计原则**——来源渠道本身就是敏感信息；历史重写要在第一次提交前想清楚，而不是事后补救

### 主题四：学习管理——验收标准之外还有什么

Jerry 档案初版只写验收 checkbox，发现"我和我的实际学习不相关"；追问后承认自己也"不知道在学什么"——进而发现学习管理需要双层模型（验收层 + 学习状态层），且创始人自身的学习需要主题制而非验收制。

- 学到：**档案模型要先回答"记录谁的学习"**——学员（验收制）与自助学习者（主题制）是两种档案；模型缺陷只有在使用中暴露

## 自学方法观测

- 与 AI 协作时的关键动作是**否决与纠偏**：四轮形态收敛、三次档案定义修正，每次否决都在逼近自己的真实意图
- "不知道在学什么"的解法：**从决策记录里考古**——学到了什么藏在每个否决和修正里

## 自举：学习任务与验收标准（探路者把自己当 follower 记账）

按今日新立的模型自举：iGuo 既是探路者（今天的实践已发生），也尝试把自己当天产生的学习效果用 follower 的方式记账——列举学习任务（Task）与验收标准。这是学习云模型第一次对自己套用。

### Task 1：组织模式提炼——从档案实践考古出内核与标准语言

- **做了什么**：追问组织档案体系多篇归纳"不够本质"，把六条罗列收敛为内核一句话（外化在场），再定名"民主与法治"，确认否决权=程序约束的熔断位
- **验收标准**：能向不了解量潮的人用两三句话说清组织模式的内核，且量潮成员听到后认可"这就是我们在做的"——已达成（index.md 重写版即证据）

### Task 2：组织形态判断——实训基地形态定稿

- **做了什么**：四轮收敛实训基地组织形态（复用/预备部门 → 必须编组 → 内包子公司 → 职能部门编组），每轮否决 AI 方案并给出尺子
- **验收标准**：形态能同时满足三问——训练现场是否真实组织？编组是否真实？父子关系是否表达清楚？——内包子公司+四部门编组通过三问，写入 structure.md

### Task 3：档案体系分组——组织/人物两组与四件套

- **做了什么**：orgs/people 分组重构（git mv 保留历史）、structure/institution/culture 三类档案分离、人物一等实体（一人一档跨组织职务）
- **验收标准**：新组织/新人物加入时无需讨论"放哪、建什么文件"——README/AGENTS 模板可直接套用； qtalliance 拆分实例验证通过

### Task 4：隐私与解密尺度——脱敏作为档案设计原则

- **做了什么**：Jerry 日志脱敏三连（代号化→删来源→filter-repo 全历史重写×2），删除站点对档案的路径引用
- **验收标准**：任意历史版本 `git log --all -S` 对真实姓名/来源渠道零命中——已验证通过

### Task 5：学习管理模型——双账本分工与 Schedule 模型

- **做了什么**：发现"验收标准与实际学习不相关"→ 双变体档案（学员验收制/自助主题制）→ 探路者-follower 本质 → Schedule+Task 核心模型（Task 自足）→ 与执行云两本账分工
- **验收标准**：模型能同时解释 Jerry 档案、iGuo 档案、gallery checklist 三种现存形态，且能指出哪些是模型、哪些是数据视图——已达成（insight/schedule-core-model.md 即证据）

### Task 6（进行中）：站点改组——组织/人物双导航

- **做了什么**：qtorg site v0.2.0/0.2.1——路由重构 /orgs/* 与 /people/*、人物一等实体、数据抽离、学术履历区块
- **验收标准**：新人物/新组织上线只改 data 文件不改页面代码；线上深链 200——首例（樊仲琛学术履历）通过，模型待更多人物验证
