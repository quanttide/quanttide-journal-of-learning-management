# 2026-08-30 Jerry 教学组：AI 工具选型与学习方法

## 一、AI 编程工具选型：Cursor vs Zed

**工具对比结论（Jerry）**：

- **Cursor = Zed + coding agent**——功能最全，"目前看我好像最喜欢 cursor，功能蛮全乎"
- Zed：精简极客风，但 agent 弱（"Zed Agent 这么菜马，都不算 Code Agent"），UI 对新人吸引力不足
- opencode：并不适合程序员——程序员需要 IDE，"看不到代码容易失控"
- VS Code / JetBrains：学校时期用过，停留在代码补全时代，"都不如现在 Cursor"，JetBrains 太繁琐
- 选型原则（导师）："工具这个东西，趁手为主"——开源 vs 商业的区别，适合就用

**Jerry 选 Cursor 的理由**：

1. 内置优化好，rule 机制适合 AI 快速学习
2. agent 排布 + IDE 一体（"喜欢 all in one 加赏心悦目"）
3. 文件级 review 直观微元——agent 产出 diff 逐项 check / Keep，"很直观很微元"，对强控制型新人友好
4. 代价：稍贵（预估重度开发 1–2k/月，"差不多就是 Claude 超大杯"）

**导师的工作流对照**：pi web（只读观测）+ Zed（改代码）搭配，按模式切换。

## 三、学习方法论（本次交流的核心沉淀）

1. **仓库即上下文**：把优秀理论仓库、step-by-step 仓库、量潮仓库单独放好，让 Cursor 带着学，不懂就把仓库当上下文——"蛮高效"；官方文档/官方 repo clone 到本地喂给模型出学习计划，对着写 demo，理解后反哺 vibe coding
2. **Obsidian 分工**：obsidian 单仓交给 Cursor 管理，ob 只负责同步和读
3. **把机械 prompt 封装成 skill**：将原先机械的 prompt 封装为稳定触发的 skill，接驳到 domain 大脑级项目，配合模板批量输出——"这样 intention、insight、quickview、roadmap 都好输出且成标准了"（任务 2 今日收尾，封装任务 1 精华）
4. **第二大脑范式已内化**：把第二大脑范式直接搬来当实践仓库的文件排布；导师确认："第二大脑本身就是一个标准化积木单元，你需要什么往里堆什么就行，不需要一个完整框架解决所有问题"
5. **个人金句（AI 协作观）**：
   - "当你无法判断 AI 行为的时候，去学习吧，别 coding 了"
   - 目标：积累足够多的细分结构化文档，"当开发经验足够成熟时，通过 AI 直接完成一场巨大的填词游戏"
   - "vibe coding 能成企业级交付产品是个伪命题——没有 SDE 经验安全那关过不了"（看了导师发的视频深以为然）；"vb 卡壳了就要疯狂堆认知提升判断力了，学习没有捷径，不过 AI 可以加速罢了"
   - git 流：终端 + AI + GitHub Desktop

## 四、导师的理论升华：可观测性

Jerry 描述"通过积累结构化文档获得控制感"后，导师指出这在系统工程里叫**可观测性**（observability）：

- 对系统全貌有准确认识——Kruise、GitHub Desktop 这类工具都在起这个作用
- **控制一定建立在观测的基础之上**——控制论（系统工程三大分支之一）回答的就是怎么观测和控制
- Jerry 的 Cursor 安全感来自"可以观测"；导师评价其工程习惯"精细"，方向是"增强控制感"
